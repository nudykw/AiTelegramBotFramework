# 🛠️ Інструменти MCP (Model Context Protocol)

Бот підтримує **Model Context Protocol (MCP)**, що дозволяє ШІ-моделям динамічно використовувати зовнішні інструменти (такі як веб-пошук або Puppeteer) для відповіді на запитання.

## 🚀 Як це працює

1.  **Tool Hub**: Бот виступає як MCP Client за допомогою `McpServerManager`. Він може підключатися до кількох MCP серверів.
2.  **Ізольоване виконання**: Усі MCP сервери запускаються всередині спеціалізованого Docker-контейнера (`gpt_mcp_runtime`) для забезпечення безпеки та ізоляції залежностей (наприклад, Chromium для Puppeteer).
3.  **Автоматичний сидінг (Seeding)**: При старті бот зчитує список `McpSettings:DefaultTools` з `appsettings.json` і автоматично реєструє або оновлює ці інструменти в базі даних.
4.  **Перевірка працездатності (Health Checks)**: Під час ініціалізації бот перевіряє зв'язок з кожним інструментом і записує результат у лог:
    - ✅ `[HEALTH CHECK PASSED]` — Інструмент готовий до використання.
    - ❌ `[HEALTH CHECK FAILED]` — Інструмент недоступний або не вдалося запустити.
5.  **Динамічне виявлення**: Бот отримує список доступних інструментів від активних MCP серверів.
6.  **Інтеграція з моделлю**: Інструменти передаються ШІ-моделі (OpenAI, Gemini тощо) як "функції".
7.  **Виконання інструментів**: Коли ШІ вирішує використати інструмент, бот виконує його через `docker exec` у контейнері середовища виконання та надсилає результат назад до ШІ.

## 🧩 Вбудовані інструменти MCP (Native Tools / In-Process)

Окрім зовнішніх MCP-серверів, що запускаються в Docker, бот підтримує **Вбудовані інструменти MCP (Native MCP Tools)**, які реалізовані безпосередньо на C# в проекті `ServiceLayer`. Ці інструменти виконуються всередині того ж процесу, що й бот, забезпечуючи високу швидкість роботи, безпечний доступ до внутрішніх сервісів та контексту (такого як поточний ID користувача).

### 📁 Інтеграція з пісочницею Google Drive

Ми надаємо безпечну ізольовану віртуальну файлову систему в Google Drive за допомогою нативного Google Drive API (v3). Вона обмежує ШІ-агента суворою пісочницею та вимагає обов'язкових описів для кожного файлу.

#### Ізоляція пісочниці та безпека
- **Ізоляція кореневої папки**: Усі операції з файлами суворо обмежені однією папкою з назвою `AppWorkspace_{UserId}` (де `{UserId}` динамічно визначається з активного контексту користувача `McpContext.UserId`). Якщо ця папка не існує, вона створюється автоматично при першому запиті.
- **Захист від Path Traversal**: Файли в Google Drive ідентифікуються випадковими буквено-цифровими ID, а не класичними шляхами. Наші інструменти рекурсивно сканують робочий простір користувача, будують карту всіх дозволених дочірніх ID файлів/папок та обчислюють їхні віртуальні шляхи (наприклад, `/docs/spec.md`). Будь-яка спроба виконати дію з `fileId` або `parentId`, який відсутній у цій карті, миттєво блокується з виключенням `UnauthorizedAccessException`.
- **Валідація імен файлів**: Імена файлів не можуть містити символів обходу шляху, таких як `/`, `\`, або `..`.

#### Дозволені файли
- Інструменти працюють виключно з **папками** (`application/vnd.google-apps.folder`) та **Markdown-файлами** (розширення `.md` або mime-тип `text/markdown`).

#### Обов'язкові описи
- ШІ-агенту потрібен контекст файлів без їх скачування. Кожен файл або папка, які створюються або перераховуються, **обов'язково** повинні мати опис, який записується в нативне поле `description` метаданих Google Drive API.

#### Доступні інструменти
1. `gdrive_list` — Рекурсивно отримує дерево файлів і папок у робочій папці разом з їхніми ID, віртуальними шляхами та описами.
2. `gdrive_read(fileId)` — Завантажує та повертає весь текстовий вміст Markdown-файлу за його `fileId`.
3. `gdrive_write(fileId, content)` — Оновлює текстовий вміст існуючого Markdown-файлу.
4. `gdrive_create(name, type, description, parentId)` — Створює нову папку або порожній markdown-файл із обов'язковим записом опису в метадані.
5. `gdrive_update_description(id, newDescription)` — Оновлює опис файлу або папки в метаданих.
6. `gdrive_delete(id)` — Переміщує файл або папку в кошик Google Drive. Видалення самої кореневої папки робочого простору заблоковано.

### 🔑 Вбудовані SSH інструменти (ssh_execute)

Ми надаємо безпечний, вбудований SSH-інструмент, який виконує консольні команди на віддаленому сервері Linux, використовуючи файл приватного ключа, що зберігається безпосередньо в ізольованій пісочниці Google Drive користувача.

#### Багатокористувацька ізоляція та безпека в пам'яті
- **Ніяких локальних файлів**: Приватні ключі ніколи не записуються на локальний диск контейнера або хост-машини. Вони завантажуються з робочого простору Google Drive безпосередньо в оперативну пам'ять на час з'єднання і миттєво знищуються.
- **Сувора ізоляція користувачів**: Сесії підключення та ключі ізольовані за допомогою контексту активного користувача (`McpContext.UserId`). Один користувач ніколи не зможе отримати доступ або перехопити активну SSH-сесію чи ключ іншого користувача.
- **Дозволені файли в пісочниці**: Пісочниця Google Drive дозволяє завантаження стандартних назв SSH-ключів (що починаються з `id_`), конфігурацій (`config`) та розширень ключів (`.pem`, `.key`) на додачу до стандартних `.md` файлів.

> [!WARNING]
> **Обмеження безпеки лише для власника бота**: Приватні ключі та конфігураційні файли, завантажені на Google Drive, технічно доступні власнику бота (оскільки власник бота повністю контролює середовище виконання додатка, базу даних та конфігурацію клієнта Google Drive). Через це використання функціоналу SSH MCP **категорично рекомендується виключно власнику бота**.
> 
> **Обмеження доступу**: Інструмент `ssh_execute` фільтрується динамічно і **видимий та доступний для виконання тільки для налаштованого Власника бота** (на основі `OwnerId` в конфігурації). Користувачі, які не є власниками, не можуть бачити або викликати цей інструмент.
> 
> **Юридична відмова від відповідальності та заборони**: Власнику бота суворо заборонено використовувати цей функціонал SSH MCP для перехоплення, отримання або викрадення приватних ключів інших користувачів бота (як шляхом модифікації коду, так і через будь-які інші адміністративні методи доступу). Такі дії кваліфікуються як кіберзлочин і тягнуть за собою сувору **кримінальну ответственность (кримінальну відповідальність)** відповідно до чинного місцевого та міжнародного законодавства. Розробники/автори цього програмного забезпечення не несуть абсолютно **ніякої відповідальності** за будь-які подібні несанкціоновані дії, порушення безпеки або законодавства, вчинені власником бота.

#### Доступні інструменти
1. `ssh_execute` — підключається до віддаленого Linux-хоста та виконує консольну команду в пам'яті.
   - `host` (string, обов'язковий): IP-адреса або доменне ім'я віддаленого сервера.
   - `port` (number, за замовчуванням 22): SSH-порт.
   - `username` (string, обов'язковий): SSH-ім'я користувача.
   - `keyFileId` (string, обов'язковий): Google Drive ID файлу приватного ключа.
   - `command` (string, обов'язковий): Команда для виконання.
   - `timeout` (integer, за замовчуванням 30000): Таймаут виконання в мілісекундах.

#### 🛡️ Генерація SSH-ключів та найкращі практики безпеки
Для забезпечення абсолютної безпеки віддалених середовищ дотримуйтесь таких правил:
1. **Згенеруйте окремий ключ**: Завжди створюйте виділену пару SSH-ключів для бота. Ніколи не використовуйте повторно свої персональні ключі. Використовуйте сучасний формат Ed25519 без парольної фрази (оскільки бот працює в автоматичному режимі):
   ```bash
   ssh-keygen -t ed25519 -f id_mcp_key -N "" -C "tg-bot-mcp-key"
   ```
2. **Виділений обмежений користувач**: Створіть окремого користувача без root-прав (наприклад, `mcp-agent`) на цільовому сервері:
   ```bash
   sudo useradd -m -s /bin/bash mcp-agent
   ```
   Встановіть публічний ключ `id_mcp_key.pub` у файл `~mcp-agent/.ssh/authorized_keys` зі стандартними правами доступу UNIX (`600`).
3. **Обмеження прав Sudo**: Якщо боту потрібно виконувати привілейовані команди, налаштуйте `/etc/sudoers`, щоб дозволити `NOPASSWD` *виключно* для конкретних необхідних команд, замість повного root-доступу:
   ```text
   mcp-agent ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart my-service
   ```
4. **Зберігання на Google Drive**: Завантажте ваш приватний ключ `id_mcp_key` та файл `config` безпосередньо у папку `.ssh/` вашого робочого простору Google Drive, щоб ШІ міг знайти їх через `gdrive_list` та використовувати динамічно.

### 🔑 Налаштування облікових даних

Додайте блок конфігурації `GoogleDriveSettings` у розділ `AppSettings` файлу `appsettings.json` або у змінні оточення (OAuth використовується за замовчуванням):

```json
"AppSettings": {
  "GoogleDriveSettings": {
    "AuthType": "OAuth", 
    "ClientSecretsPath": ".secrets/client_secrets.json",
    "ServiceAccountKeyPath": ".secrets/service_account.json",
    "TokenStorePath": ".secrets/token_store",
    "RootFolderTemplate": "AppWorkspace_{UserId}",
    "DefaultUserId": "default"
  }
}
```

#### Методи авторизації:
1. **OAuth 2.0 (За замовчуванням)**: Покладіть ваш файл секретів клієнта за шляхом `ClientSecretsPath` (наприклад, `.secrets/client_secrets.json`). Сховище токенів буде автоматично створено в `.secrets/token_store/`. Якщо параметр `AuthType` пропущено, автоматично вибирається `OAuth`.
2. **ServiceAccount**: Покладіть ваш JSON-файл ключа сервісного акаунта за шляхом, вказаним у `ServiceAccountKeyPath` (наприклад, `.secrets/service_account.json`), та явно вкажіть `"AuthType": "ServiceAccount"` у конфігурації.

> [!WARNING]
> Тримайте ваші секретні ключі в безпеці! Папка `.secrets/` автоматично додана до `.gitignore` і **ніколи** не повинна потрапити до репозиторію.

## 🔒 Виробничий шлюз телеметрії та БД (Prod MCP Gateway для IDE)

Для розробки в IDE (наприклад, Cursor, VS Code, Windsurf) ми надаємо безпечний, керований розробником MCP-сервер (`.agent/prod-mcp-gateway.js`), який дозволяє агентам вашої IDE безпечно робити запити до виробничої бази даних PostgreSQL та отримувати логі .NET Aspire через мережу Tailscale суто через структуровані API.

### 🛡️ Основні можливості та заходи безпеки
1. **Явна активація демона**: Шлюз **ніколи** не підключається до продакшну автоматично. Ви повинні явно запустити його, виконавши команду `node .agent/prod-mcp-gateway.js --daemon` у своєму терміналі. Коли демон вимкнено, клієнт IDE не надає жодних інструментів.
2. **Дворівнева пісочниця SQL**: Інструмент запитів до бази даних виконує лише інструкції `SELECT`, `EXPLAIN`, `SHOW` або `DESCRIBE`, а також застосовує блокування за регулярними виразами для запобігання будь-ям пов'язаним або вкладеним інструкціям модифікації (таким як `INSERT`, `UPDATE`, `DELETE`, `DROP`).
3. **Залежність від мережі Tailscale**: Безпечно підключається до приватної IP-адреси Wireguard Tailscale вашого сервера (`100.82.239.59`). Якщо Tailscale вимкнено, усі запити негайно завершуються помилкою.

### 🛠️ Доступні інструменти для ШІ-агентів в IDE
1. `query_prod_database(sql)` — безпечно виконує запит лише на читання до виробничої БД та повертає чисту, відформатовану таблицю Markdown.
2. `get_prod_logs(service_name, limit, filter)` — підключається до HTTP REST API .NET Aspire (`/api/telemetry/logs`), розгортає JSON-логи OTLP і повертає чистий хронологічний потік логів.
3. `get_prod_resources()` — перераховує всі запущені виробничі сервіси та їхні стани, зареєстровані в Aspire Dashboard.

### 🚀 Налаштування та використання
1. Підключіться до **Tailscale** на вашому локальному комп'ютері.
2. Переконайтеся, що віддалений REST API Aspire Dashboard увімкнено на вашому виробничому сервері, додавши `DASHBOARD__API__DISABLED: "false"` до змінних оточення `aspire-dashboard` у `docker-compose.yml` та перезапустивши його.
3. Запустіть демон шлюзу у своєму терміналі:
   ```bash
   node .agent/prod-mcp-gateway.js --daemon
   ```
   *(Примітка: Скрипт автоматично перевірить та встановить Node.js драйвер PostgreSQL `pg` під час першого запуску).*
4. Попросіть свого агента IDE описати схему виробничої бази даних або отримати логі.
5. Натисніть `Ctrl+C` у своєму терміналі, щоб зупинити демон і миттєво припинити будь-який доступ до продакшну.

## 📂 Керування інструментами

Інструменти керуються через базу даних у таблиці `McpTools`, при цьому початковий стан задається конфігурацією.

### Адміністративна команда
- `/tools` — Відображає список поточних активних інструментів та їх описи.

### Конфігурація (`appsettings.json`)
Ви можете визначити інструменти за замовчуванням, які будуть автоматично додані до бази даних:

```json
"McpSettings": {
  "DefaultTools": [
    {
      "Name": "Web Search (DDG)",
      "Command": "npx",
      "Args": "[\"-y\", \"@oevortex/ddg_search\"]",
      "EnvVars": "{}"
    }
  ]
}
```

### Колонки бази даних (таблиця `McpTools`)

| Колонка | Опис | Приклад |
|---|---|---|
| **Name** | Унікальна назва | `Puppeteer` |
| **Command** | Команда для запуску | `npx` |
| **Args** | JSON-масив аргументів | `["-y", "@modelcontextprotocol/server-puppeteer"]` |
| **EnvVars** | JSON-словник змінних оточення | `{"DEBUG": "mcp:*"}` |
| **IsActive** | Увімкнути/Вимкнути | `true` |

## 🧪 Тестування інструментів

Ви можете перевірити роботу інструментів наступним чином:
1. Перевірте стартові логи на наявність `[HEALTH CHECK PASSED]`.
2. Виконайте команду `/tools` у Telegram.
3. Задайте боту питання, яке потребує використання інструменту (наприклад, "Знайди останні новини про .NET 10").

## ⚠️ Інфраструктура
- **Dockerfile.mcp**: Визначає середовище для інструментів MCP (Node.js 22 + Chromium).
- **Змінна оточення**: `MCP_RUNTIME_CONTAINER` повинна вказувати на назву контейнера середовища виконання (за замовчуванням: `gpt_mcp_runtime`).
