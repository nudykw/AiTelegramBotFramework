# 🧠 Посібник з оптимізації ШІ-розробки та економії токенів

🇺🇸 [English](./AI_AGENT_WORKFLOW.md) | 🇺🇦 **Українська**

Ласкаво просимо! Цей посібник описує, як налаштувати та запустити сучасне ШІ-кероване середовище розробки у цьому репозиторії.

> [!IMPORTANT]
> **Чому це критично важливо для розробника**:
> Під час роботи з сучасними ШІ-агентами (в Cursor, Windsurf, Roo Code або Claude Desktop) зчитування повних файлів коду або документації витрачає мільйони токенів моделі, швидко заповнює контекстне вікно, сповільнює відповіді ШІ та значно здорожчує розробку.
> Для вирішення цієї проблеми ми пропонуємо **два взаємодоповнюючі MCP-інструменти для економії токенів**, які знижують споживання контексту **більш ніж на 90%**, надаючи ШІ-агенту точний і вичерпний контекст по всьому репозиторію.

---

## 🛠️ Основні MCP-інструменти для ШІ-агента

У проєкті налаштовано три фонові шлюзи (MCP-демони) для взаємодії з ШІ-агентом. Вони виконують різні завдання, працюють паралельно і не конфліктують:

| Інструмент | Призначення та Спеціалізація | Порт | Технології / Драйвер |
|---|---|---|---|
| **`mcp-gateway.js`** | **Аналіз структури коду (Codegraph)**: класи, методи, типи та навігація графом викликів | `12666` | Codegraph (Rust / SQLite) |
| **`project-memory-mcp.js`** | **Семантична пам'ять (Graph-RAG)**: швидкий пошук контексту у файлах проєкту офлайн | `13585` | ONNX-ембеддинги / Локальне сховище |
| **`prod-mcp-gateway.js`** | **Діагностика системи (Diagnostics Gateway)**: безпечний аналіз логів (.NET Aspire) та запити до БД для ШІ-агента (зокрема, безпечно на продакшні через [Tailscale](https://tailscale.com/)) | Динамічний / `13585` | PostgreSQL / .NET Aspire logs |

## 🚀 Швидкий старт (Налаштування на новій машині)

Коли ви вперше клонуєте цей репозиторій на нову машину, виконайте такі кроки для запуску середовища:

### Крок 1: Встановіть SurrealDB (Якщо ще не встановлено)
Наш семантичний Graph-RAG працює на базі СУБД **SurrealDB**. Вона надзвичайно швидка і працює локально:
- **Linux / macOS**:
  ```bash
  curl -sSf https://install.surrealdb.com | sh
  ```
- **Windows (PowerShell)**:
  ```powershell
  iwr https://install.surrealdb.com -useb | iex
  ```
Запустіть службу SurrealDB на порту `3004` (із конфігурацією за замовчуванням, яку очікують наші скрипти):
```bash
surreal start --bind 0.0.0.0:3004 --user root --pass root surrealkv:database.db
```

### Крок 2: Налаштуйте файл `.env`
Скопіюйте файл `.env.example` у файл `.env` у корені проекту та переконайтеся, що ваші API-ключі або підключення до БД налаштовані правильно:
```bash
cp .env.example .env
```

### Крок 3: Запустіть MCP-демони
Відкрийте окремі вікна терміналу та запустіть необхідні демони:

1. **Запустіть демон структури коду (Codegraph)**:
   ```bash
   node .agent/mcp-gateway.js --daemon
   ```
2. **Запустіть демон семантичної пам'яті (Graph-RAG)**:
   ```bash
   node .agent/project-memory-mcp.js --daemon
   ```
   *(Примітка: Під час першого запуску скрипт автоматично встановить потрібні бібліотеки Node.js та завантажить локальну модель ембеддингів розміром ~23 МБ для розрахунку 100% офлайн).*
3. **Запустіть шлюз діагностики логів та БД (Опціонально)**:
   ```bash
   node .agent/prod-mcp-gateway.js --daemon
   ```
   *(Примітка: Надає ШІ-агенту можливість аналізувати системні логі .NET Aspire та безпечно виконувати SELECT-запити до бази даних у режимі "тільки читання" для діагностики роботи бота — зокрема, безпечно на продакшні за допомогою [Tailscale](https://tailscale.com/)).*

## 🔒 Гарантії безпеки та конфіденційності

1. **100% Локальні вектори**: Векторні ембеддинги розраховуються повністю локально у JavaScript/Wasm через ONNX Runtime. **Жодні файли коду, специфікації чи конфігурації ніколи не надсилаються на зовнішні сервери або API.**
2. **Явний контроль запуску**: Клієнт IDE ніколи не запустить демони автоматично. Доступ до БД та продакшну залишається повністю закритим, доки ви не запустите команди `--daemon` вручную.
3. **Захист на рівні читання**: Інструменти для роботи з базами даних суворо обмежені операціями читання, блокуючи будь-які спроби виконати вкладені деструктивні запити (`INSERT`, `UPDATE`, `DELETE`, `DROP`).
